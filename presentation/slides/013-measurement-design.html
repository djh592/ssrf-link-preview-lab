We measure both security and the usefulness of normal previews.

The Web UI showed individual explanatory runs through the testbed. Those runs illustrate the mechanisms; they are not the repeated measurements. We now define the controlled comparison behind the findings. We compare five policies in the same preview pipeline. For each HTTP scenario, we run each policy 50 times. First, do the defenses preserve normal previews? We test a direct page, a one-redirect page, and a three-redirect page. Three scenarios times five policies times fifty repetitions give 750 trials. A normal preview succeeds when the expected title and description return within the timeout. We report success and median and P95 latency for successful previews. Second, can an attacker cause an internal request? Four scenarios test a direct private IP, a stable private service name, and one- and three-hop redirects to the report. Four times five times fifty gives 1,000 trials. We distinguish report access from marker disclosure. All 1,750 HTTP trials have complete evidence. Separately, four individual recursive-DNS probes connect DNS answers to the HTTP peer and report-service events. They illustrate behavior under the tested TTL and cache conditions, not an attack rate. The browser demo uses individual explanatory runs and is not included in the trial counts.
