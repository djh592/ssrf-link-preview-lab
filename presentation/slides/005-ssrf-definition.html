Server-Side Request Forgery (SSRF)

In a USENIX Security '24 study of 27,078 open-source PHP applications, researchers identified 237 flows where user input reached a server-side request. Of the 158 application flows, 39 were trivially exploitable; the manual analysis found only two applications with safe server-side request features.

SSRF Occurs When a Server Does Not Ensure Its Request Reaches the Expected Destination.

MITRE classifies this weakness as CWE-918. The definition centers on destination control: a server retrieves a user-influenced URL without sufficiently ensuring that the request reaches the expected destination. Returning the response to the user is one possible consequence, but it is not required for the server-side request itself to be an SSRF risk. A 2024 study examined 27,078 open-source PHP applications and identified 237 flows in which user input reached a server-side request. The authors classified 158 as application flows, 71 as hacking-tool flows, 7 as test flows, and 1 as an example. Of the application flows, 39 were trivially exploitable, 18 were false positives, and 101 required further analysis. The manual analysis found only two applications with safe server-side request features. These results are scoped to the studied PHP applications, not an estimate for every web system.
