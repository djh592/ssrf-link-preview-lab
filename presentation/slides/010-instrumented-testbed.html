How Do We Evaluate Link-Preview Fetch Policies?

Our Testbed Links Each Policy Decision to the Request Path Actually Observed.

To answer the research question, we built an instrumented link-preview testbed. Each trial combines a controlled scenario with one fetch policy and runs through the same preview pipeline. A trial identifier links the policy decision to the HTTP peer actually contacted and to independent events from the destination service. This lets us compare what a policy intended to block with what the system actually reached. The contribution is the controlled and observable evaluation environment, not a new general-purpose SSRF defense. Transition with: "To interpret that evidence, we first need to define what the attacker controls and which network boundary the preview service must protect."
