Motivation

URL Approval ≠ Connection Identity

Mechanisms: OWASP SSRF Prevention Cheat Sheet

A Destination Can Change After It Is Approved.

Checking only the submitted URL is not enough, because the destination can change after that check. Here are two ways this can happen. [Click] First, consider an HTTP redirect. [Click twice] The attacker submits a public URL, so the initial check allows it. The preview service then requests the public redirect server. [Click] The server now redirects the request to the internal report. [Click twice] If the preview service follows this redirect without checking the new URL, it reaches the private resource and returns its content to the attacker. [Click] The second method is DNS rebinding. [Click three times] This time, the URL does not change. The attacker submits a domain name, and its first DNS response gives a public address. That address passes the policy check. [Click twice] Later, when the service opens the connection, the same domain is resolved again. The attacker now returns a private address. [Click twice] The request reaches the internal report, and the report preview is returned to the attacker. Whether this works in practice depends on DNS caching and client behavior, but the checked address and the connected address can be different. [Click] In both cases, the destination changes after it has been approved. A redirect changes the URL, while DNS rebinding changes the address behind the same URL.
