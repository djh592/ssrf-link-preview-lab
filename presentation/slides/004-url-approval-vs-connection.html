Mechanisms: OWASP SSRF Prevention Cheat Sheet

A Destination Can Change After It Is Approved.

Start with the title only. Advance once to show Method 01 and the three participants. Advance again: the attacker submits a public redirect URL, which the preview service allows. Next, the service requests the redirect server. The server returns a private Location. The service then requests the internal report without revalidating the new target. Finally, the report returns through the preview service to the attacker. Advance to clear the first sequence and introduce Method 02 with the same three base participants. The attacker submits rebind.lab. The preview service then resolves it for policy validation, introducing the recursive resolver and attacker-controlled authoritative DNS server. Their public response passes the address check. During connection setup, a second query returns a private address. The service requests the internal report, which returns through the preview service to the attacker. Cache state, TTL, resolver behavior, and the HTTP client's connection path determine whether this sequence succeeds in practice. These are conceptual mechanisms, not project results. Advance once more for the common conclusion: the destination can change after the initial approval, whether a redirect replaces the URL or a later DNS answer changes its address.
