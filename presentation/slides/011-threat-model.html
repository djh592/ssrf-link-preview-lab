Where Is the Trust Boundary?

The Attacker Controls the URL Path into a Preview Worker That Can Reach the Protected Report.

This is the isolated measurement topology, not the public browser-demo overlay. The attacker controls only the submitted URL and the responses produced by the external web and authoritative DNS fixtures. There is no host-published route to the synthetic internal report, and the attacker cannot modify Preview, the recursive resolver, or the report. Preview is the application HTTP-fetch path that can reach both the untrusted service and the protected report. In the DNS overlay, the recursive resolver also joins the lab networks so it can resolve their service names; it is DNS infrastructure, not an HTTP proxy. The dashed red line is the attack goal, not a measured result. A request arriving at the report is the primary security outcome; returning its marker is tracked separately as disclosure. Transition with: "This boundary gives us one design rule: every request must be authorized against the destination it actually reaches."
