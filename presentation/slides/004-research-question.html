Research question | Two goals

Can We Block Private Access Without Breaking Public Previews?

Security

Keep private resources unreachable.

Block requests to the internal report and prevent its protected marker from returning.

What we measure Internal request reached? Protected marker returned?

Preview utility

Keep legitimate previews useful.

Preserve successful direct and allowed redirected previews while measuring added latency.

What we measure Preview success Median / P95 latency

A useful defense must satisfy both goals.

This question has two equally important sides. First, security: a protected internal report must not receive the request, and its marker must not be disclosed. Second, preview utility: legitimate direct and allowed redirected previews should still work, while the policy's added latency remains visible. Rejecting every outbound request would make the feature useless, so the evaluation must measure both outcomes. Reveal the takeaway only after both goals are visible. The exact policies come later, after the testbed is introduced. Transition: "To answer both sides, we needed a working preview environment and evidence beyond the preview response itself."
