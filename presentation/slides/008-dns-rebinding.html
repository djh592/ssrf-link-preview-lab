How Can the Same Hostname Reach a Different Address?

A DNS Check Protects the Connection Only If the Client Uses the Checked Address.

DNS creates a subtler destination change than an HTTP redirect. During validation, the hostname may resolve to a public address and pass the check. If the client performs another lookup when it connects, the same hostname may then resolve to a private address. The path succeeds only if that later answer is used for the connection; resolver caching, TTL, timing, and client behavior determine whether this happens. A changed DNS answer alone therefore does not prove an internal connection—we also need the actual connection peer. This is a conceptual mechanism. The browser demo models the connection-stage answer, while the separate recursive DNS probe is the path for observing resolver behavior.
